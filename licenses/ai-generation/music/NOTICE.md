# 音乐模型与推理运行环境

音乐生成采用独立、按需安装的推理运行环境。模型权重不随应用安装包分发。

- 推理源码：`ace-step/ACE-Step-1.5`，固定提交 `ca1e85fe9430179831e6bc6be790c332190a3866`。
- 源码归档：`https://codeload.github.com/ace-step/ACE-Step-1.5/tar.gz/ca1e85fe9430179831e6bc6be790c332190a3866`。
- 归档 SHA-256：`b464c11f00af00e1e089a09f58a03962f803c080f116fd0517dbe5ec839706b3`。
- 快速模型：`ACE-Step/Ace-Step1.5`，固定版本 `19671f406d603126926c1b7e2adc169acbcade22`。
- 常规模型：`ACE-Step/acestep-v15-sft`，固定版本 `c410d249e71ea9385a7b586865e65b1473e1098d`。
- 两种模型共用前者提供的 `Qwen3-Embedding-0.6B` 文本编码器与 `vae`。每个完整模型约 6.34 GB；相同文件可复用。

模型仓库声明使用 MIT 许可，原文保存为 `ACE-Step-MIT.txt`。文本编码器及部分推理源码使用 Apache-2.0，原文保存为 `Qwen3-Embedding-Apache-2.0.txt`；运行环境保留各源码文件中的版权声明。第三方依赖的许可随运行环境分发。

本项目适配层 `scripts/ai-music-runner.py` 不修改权重，也不从模型目录加载 Python 代码。它直接引用固定版本运行环境中的模型类，以 `local_files_only=True` 读取已校验的本地文件。该适配层对子类进行以下明确调整：

1. 初始化时仅验证已声明的三个模型组件，关闭上游为可选语言规划模型自动下载的路径。
2. 关闭模型目录代码同步，使用运行环境内的固定类定义；关闭即时编译及可选后端自动初始化。
3. 根据真实解码器调用回报采样进度，关闭上游基于计时器估算的百分比。
4. 当前启用提示词、歌词、纯音乐、时长、节拍、调式及种子控制，不启用语言规划、音频续写或风格参考。

默认优先使用受支持的 GPU，并允许主应用在 GPU 失败后用独立进程回退到 CPU。低内存模式在组件不工作时卸载到 CPU；这不能保证任意设备都能生成长音频。模型完整生成的音质和跨设备耗时需通过实际权重测试确认，契约检查不等于音质验证。
