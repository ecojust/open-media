# Open Media 功能与性能检查

本轮围绕录屏、截图、视频剪辑、配音、GIF、视频转换、图片编辑、保存和 MCP 检查性能。基线为 `v0.2.2`，优化代码为 `7f333f01c8b89abdc6f4946313f1fcb09865e01e`。没有调整版本号或发布安装包。

## 实测改进

以下是同一 Linux 容器内的受控测量。视频、图片和语音使用真实生成的素材；各性能测试串行执行。不同测试的计量范围不同，不能把单项倍数解释为整个软件加速倍数。

| 场景与计量范围 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 1080p、70 片段、12 个同时显示字幕及碎片转场：每帧 JS 合成平均耗时 | 5.02 ms | 3.96 ms |
| 同一预览场景：每帧 JS 合成 P95 | 9.40 ms | 8.40 ms |
| 4K 图片、10 万笔触点：拖动文字至下一帧响应中位数 | 879.5 ms | 16.7 ms |
| 70 片段：编辑状态更新中位数，不含 UI 绘制 | 5.09 ms | 0.78 ms |
| 1000 片段：编辑状态更新中位数，不含 UI 绘制 | 80.10 ms | 7.05 ms |
| MCP 真实任务控制器，30 条 × 512 KiB 模拟图像负载：状态列表读取中位数 | 7.792 ms | 0.122 ms |
| 60 秒源视频末尾截取 2 秒并转换：三次中位数 | 2.735 s | 0.525 s |
| 两个远端区间生成 GIF：三次中位数 | 0.667 s | 0.306 s |
| 60 个同源片段准备导出图：三次中位数，不含编码 | 324 ms | 7.37 ms |

主要改动：

- 字幕缓存折行和文字测量结果，文本、框宽、字体与字体加载变化时失效。缓存有数量和总字符上限。动画、滤镜和转场仍正常绘制。
- 时间线拖动使用浅响应工程快照，取消重复的深层遍历；画幅未变时保留画布。
- 图片拖动只重绘活动标注，复用前后静态图层；松开时提交一次完整数据。转换完成或失败后释放临时画布。
- MCP 界面只读取状态摘要，避免每次进度更新复制全部历史图像。协议获取任务结果仍返回完整内容。
- 视频和 GIF 尽早定位所需区间，GIF 先降帧再缩放；同一导出任务内复用同源音轨探测。

准确性检查包括 23 种文字和字体变化、6 个动态画面的缓存/直接绘制逐像素比较、图片最终画面一致性，以及撤销、重做、取消、图层顺序和真实格式导出。原生截取覆盖变帧率、长关键帧间隔、音视频偏移和非零时间戳，解码后的画面及音频与旧路径完全一致。

暂停稳定后预览没有持续重绘，同一顺序视频最多保留两个临近解码器，销毁后没有残留媒体源。全部本地测量数据见 [measurements.json](measurements.json)。测量先于提交完成，因此部分环境记录中的 HEAD 仍是基线；测量的优化工作区随后提交为上述代码版本。

## 功能回归

所有以下工作流已成功结束，验证代码均为 `7f333f01c8b89abdc6f4946313f1fcb09865e01e`：

- [完整功能与性能检查](https://github.com/ecojust/open-media/actions/runs/39200471904)：逻辑测试、全部工作区浏览器交互、真实媒体转换与导出、标准客户端 MCP 编辑，以及 Windows、macOS ARM64、macOS x64 原生检查。
- [系统预览合成](https://github.com/ecojust/open-media/actions/runs/39200471762)：两种 Mac 架构的系统 WebView 真实视频、字幕、转场和滤镜合成。
- [Windows 采集检查](https://github.com/ecojust/open-media/actions/runs/39200487265)：桌面桥接编译、生成窗口的真实截图、录制准备和取消、窗口边框。

结果包括 628 项逻辑测试、67 次工作区浏览器场景执行、6 组额外画面与性能专项，以及两个状态更新基准。Linux 和两种 Mac 架构各有 273 项常规原生测试通过，Windows 为 262 项；默认标记忽略的 13 项不计入通过数。三个桌面平台随后又显式执行并通过离线语音和媒体性能基准各 1 项。标准客户端 MCP 连接与远程编辑也通过。

重点压力场景为一条 3024×1896 视频，切成 16 个视频片段，叠加 46 个文字和 8 个转场：实际打开工程，连续播放 41 秒并自动保存，随后选择轨道、跳转、模拟配额失败并恢复，最终媒体哈希和工程内容保持完整。另一个 60 素材场景验证了保存期间继续编辑、旧保存失败延迟返回，以及重载后的内容完整性。

Windows 采集专项通过 41 个不同测试。生成窗口的截图、PNG 编码与导入校验耗时为 106 ms，指定区域为 54 ms，整屏为 592 ms；这不是从按钮点击到编辑器打开的完整延迟。Mac 系统预览在 ARM64 的 26.6.2 和 x64 的 15.7.9 上验证实时合成和局部模糊，播放过程没有逐帧 IPC 或画布快照读取。

界面测试中需要操作系统对话框或设备的部分通过可控桥接验证状态流；真实采集、合成和编码另用生成窗口与媒体验证。没有自动录制用户的屏幕或麦克风。

本轮不恢复已停用的可选大语音模型逐音色 CI，不重新下载大模型。两种 Mac 托管机器的内置语音均验证了加速执行不可用后回退 CPU；没有据此声称完成 GPU 推理性能验证。托管机器的结果也不能代替用户电脑的麦克风、权限及驱动环境。平台证据摘要见 [ci-checks.json](ci-checks.json)。

## 后续优先级

1. **批次内复用配音模型进程。** 内置模型两次生成约 7.15 秒音频，耗时 1.953 / 1.906 秒；模型装载占 1.370 / 1.263 秒。短字幕批量生成会反复装载。应先实现单活动模型、有界空闲释放、完整取消与设备故障回退，避免并行装载多个大模型。
2. **大工程归档和纯脚本图片编码移到后台线程。** 保留取消、文件校验及容量限制，先测量大文件场景；本轮未据此宣称已有加速。
3. **超大时间线的局部结构共享。** 5000 片段状态更新仍约 36 ms，需要在保持跨轨校验和撤销隔离的前提下进一步减少完整克隆。

## 复现

性能测试应逐个运行，避免与其他编码或浏览器进程争用 CPU：

```sh
npm test
npm run test:browser
node tests/browser/text-layout.cjs
node tests/browser/preview-performance.cjs
node tests/browser/image-performance.cjs
node --experimental-strip-types tests/performance/mcp-history.mjs
node --experimental-strip-types tests/performance/timeline-state.mjs
cargo test --manifest-path src-tauri/Cargo.toml --locked --no-default-features --lib
cargo test --manifest-path src-tauri/Cargo.toml --locked --no-default-features --lib tests::media_performance_tests::late_segments_and_repeated_source_planning -- --exact --ignored --nocapture --test-threads=1
```

运行前安装锁定的前端依赖、浏览器及媒体运行时。可设置 `BROWSER_EXECUTABLE`、`OPEN_MEDIA_FFMPEG`、`OPEN_MEDIA_FFPROBE` 和 `OPEN_MEDIA_PERFORMANCE_REPORT`。预览基线可用 `OPEN_MEDIA_PREVIEW_REF=963c567` 单独运行；它只替换基准中的预览实现，不修改工作区。
