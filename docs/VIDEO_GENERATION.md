# 本地视频生成

“视频生成”工作区将生成结果作为普通视频素材交给剪辑工程。它不会改写录屏原件，也不会在生成过程中修改时间线。

## 生成方式

| 方式 | 输入 | 模型 |
| --- | --- | --- |
| 提示词 | 主体、动作、环境、镜头、光线与声音描述 | 基础模型 |
| 图片 | 描述及首帧、尾帧或两者 | 基础模型 |
| 参考素材 | 描述和图片、视频及可选声音参考 | 参考模型 |
| 分镜 | 按顺序排列的镜头，每镜独立描述、时长和可选首尾帧 | 基础模型 |

最多 20 个分镜，每镜请求时长为 1–15 秒。视频以 24 FPS 输出，实际帧数按模型时域规则向上对齐，界面显示预计实际时长；时间线使用成品探测出的时长。分镜可分别输出或合并。首尾帧与多素材参考不能在同一个镜头内混用。

生成设置与分镜草稿保存在本地。后台任务提供阶段、进度、耗时和取消；成品需经媒体探测确认后才加入结果列表，用户可预览、加入素材或插入时间线。失败和取消不会把尚未完成的分镜写入工程。MCP 生成采用异步任务，可查询、取消，并在完整生成后一次提交项目修改。

## 模型与设备

本地引擎使用固定版本的 `h3.c` 和 MiniMax H3 权重。当前后端面向 macOS 15 及以上的 Apple 芯片 Mac；Windows、Linux、Intel Mac 和网页端显示明确的不可用状态。

基础权重约 144 GB，参考模型增加独立的生成权重。两者相同的编码器和解码器文件可以复用。下载使用固定版本和逐文件 SHA-256，支持镜像、断点恢复、取消及完整校验后安装。模型与生成素材分开保存，不进入录屏目录，不随主应用安装包捆绑下载。

默认使用短片、较小画幅和低内存模式。低内存模式从 SSD 分阶段读取权重，其单个计算阶段内存数字不代表整机内存需求。32 GB 设备的生成速度和内存峰值需要单独实测；不可将高配置机器的基准直接当作此配置的保证。

## 缺失解码配置的修复

如果已下载的旧版模型在生成末尾报告 `cannot open video VAE config .../video_vae/source/../config.json`，原因是旧清单遗漏了 `video_vae/config.json`。此文件仅 1807 字节，含解码所需的归一化参数，不能用 `video_vae/source/config.json` 替代。

包含修复的版本会将旧安装标记为待更新。在 Info 的视频模型分类中更新即可；已验证的大权重复用，只补缺失配置。启动生成前也会检查视频及音频配置，缺失或损坏时直接指出文件，不再等待推理结束。

现有安装可以在完全退出应用后，用仓库内的小修复脚本补齐：

```bash
bash scripts/repair-video-vae-config.sh
```

脚本自带已经核验的原始配置、许可与声明，运行时完全离线，只处理固定版本的已安装模型并核对 SHA-256，不下载或改写大权重，不改动工程。非默认数据目录可作为唯一参数传入；重新运行会跳过已正确的配置。现有配置内容不符时停止，不覆盖未知文件。修复后重新打开应用再生成，失败任务的未输出画面不能从此配置补丁中恢复。

这两个小配置文件另有经过逐字节校验的官方备用来源，已锁定提交并加入下载清单：

- [基础模型配置](https://modelscope.cn/models/MiniMax/MiniMax-H3/resolve/29139ad62f28479297e305d690ee1521042133d4/FL2VA/video_vae/config.json)
- [参考模型配置](https://modelscope.cn/models/MiniMax/MiniMax-H3/resolve/29139ad62f28479297e305d690ee1521042133d4/Ref2VA/video_vae/config.json)

原文件、SHA-256 和来源记录保存在 `licenses/video-generation/MiniMax-H3/video-vae-config.json` 与相邻的 `video-vae-config-source.json`。该备用来源仅核验了这两个配置，不代表已验证全部大权重的下载。

## 验证范围

参数、下载与任务生命周期、GUI 交互和 MCP 协议分别测试。界面或协议测试使用的模拟任务仅用于验证交互，不代表模型成功生成。原生引擎提供独立的编译和 GPU 自检；真实成片质量、速度及峰值内存仍需在具有完整模型和足够磁盘空间的 Apple 芯片设备上验证。
