# 内置离线语音

安装包携带独立语音进程和中英混合模型，提供 **1 种固定女声音色**“温柔女声（中英）”。中文和英文由同一位说话人合成；调节语速不会产生新的音色，也不支持声音克隆或情绪指令。该内置声音使用 CPU，输出 16 kHz、单声道、16 位 PCM WAV。内置声音无需下载，也不依赖系统安装的声音。可选声音仅在用户主动点击卡片下载时联网获取模型；文本合成始终在本地执行。

声学模型约 75.7 MB，声码器约 53.9 MB，词典及文本处理数据合计后约 149 MB（142 MiB），另加各平台推理库。模型与声码器合计下载约 134 MB。旧项目中已经生成的音频保留；可选模型提供另外三种声音，未安装时不能选用于生成。

## 可选离线声音

内置声音与三个下载声音统一显示在同一组卡片中，固定试听随前端资源提供。三个候选分别来自独立的模型，使用用户已比较的真实原句音频：

| 下载模型 | 声音 ID | 模型下载量 | 权重许可 |
| --- | --- | --- | --- |
| ZipVoice Distill FP32 | `zipvoice_zh_female` | 约 550 MB | CC-BY-NC（上游未标具体版本） |
| F5-TTS v1 Base FP32 | `f5_zh_female` | 约 1.40 GB | CC-BY-NC-4.0 |
| Qwen3-TTS 1.7B BF16 · Serena | `qwen3_serena` | 约 4.52 GB | Apache-2.0 |

以上是十进制模型文件体积，不含平台运行组件和安装临时空间；精确大小以 `src-tauri/resources/speech-models.json` 和卡片显示为准。ZipVoice 使用随应用提供的原生语音进程及中文数字规范化；F5 和 Qwen3 使用按平台下载的共享 `python-cpu-v1` 离线运行包。组件包含固定版本的解释器和依赖，用户不需要自行安装开发环境。共享运行包已经就绪时，另一个模型只下载模型文件，下载按钮不会重复计入已安装运行包的字节数。

ZipVoice、F5 使用项目已有的合成参考音频形成固定声音，Qwen3 使用官方 Serena 声音；不开放任意人物声音克隆。三张卡片播放各自正式测试语料第 01 段的原始 MP3：**这是一款全程由AI接管并生成的软件**。试听不下载模型，不实时合成，不写入时间线。其参数、参考音频、SHA-256 和原始许可记录在 `src/assets/voice-previews/optional-manifest.json`。

下载仅接受内置目录中的模型 ID，通过 HTTPS 获取固定修订及 SHA-256 对应的文件。模型文件和平台运行组件均须完成完整性校验，才会开放文本合成；文件存在但未校验、组件缺失或平台不支持时不会显示为可用。下载有独立进度、取消及重试，后台任务不依赖配音弹窗保持打开，正常升级保留已安装资源。已就绪声音可继续使用。

模型优先使用已核验的国内来源，并提供原始来源及镜像作为备用；独立运行组件也提供多个下载地址。界面可展开查看并复制来源，下载中显示当前来源，连接或资源读取失败时自动切换。所有地址均校验同一文件长度及 SHA-256，不会替换成其他版本或精度。已完成且通过校验的文件在重试时复用；运行组件修复时也复用原有完整权重。未完成的单个文件重新下载。来源核验记录在 `scripts/optional-speech-mirror-audit.json`，不同网络的可达性仍以实际下载结果为准。

平台资源按目标系统与架构单独准备，使用独立进程在本地合成。跨平台真实推理验证以各平台工作流的实际结果为准，固定试听播放不代表该平台已经完成运行验证。测试应包含中文和空格路径、断网重启合成、安装后校验、取消及损坏资源恢复。

前两种模型的权重许可包含非商业限制，卡片显示相应用途提示；推理实现和声码器的许可单独记录。全部原始文本与来源清单位于 `licenses/application/optional-speech/` 并随应用提供。中文数字规范化兼容实现所依据的 cn2an 0.5.23 原始 MIT 许可、固定 wheel 摘要和 1,538 条独立对照样例来源也保留在该目录。旧项目已生成的音频不改写，旧模型的来源归入历史资料，不再出现在当前下载目录。

## 固定输入

`scripts/speech-runtime.lock.json` 固定每个原始归档或模型文件的来源、版本和 SHA256。运行组件采用 sherpa-onnx 1.13.8 的官方 C API 分发；声学模型采用 Matcha 中英混合女声 `model-steps-3.onnx`，使用同一发布者提供的 `vocos-16khz-univ.onnx`。这些必要依赖名和原始版权声明用于准确记录供应链。

模型元数据的 `n_speakers=1`，唯一 `speakerId` 为 0，应用声音 ID 为 `matcha_zh_en_female`。版本 2 运行清单明确标记 `model.kind=matcha`，分别列出声学模型、声码器、tokens、词典与文本规范化文件；不再使用独立音色向量文件。中英文文本均通过 UTF-8 文件送入独立进程。

模型及声码器权重来自同一上游模型仓库，该仓库声明 Apache License 2.0。发布者许可元数据、模型文件清单及摘要、原始发布说明均保留在 `licenses/speech-runtime/files/model/`；两种模型实现的原始 MIT 版权许可也予以保留。不得将实现许可当作权重许可的依据。

## 停顿与语速

默认参数与选定试听版本一致：两线程 CPU、`noise_scale=1.0`、`length_scale=1.0`；配置与单次生成的 `silence_scale` 均显式设为 0.2。此项将满足条件的合成长静音压缩至原长度的 20%，影响停顿节奏，不改变音色或增加情绪控制能力。显式设置生成参数避免仅修改模型配置而未影响实际输出。

试听和时间线配音使用同一音色和参数。语速仍由用户选择；字幕对齐读取实际音频时长，不对配音做额外变速。已有项目中的音频不会重新生成。

该版本已在 Linux x86_64 上进行 26 条中英语料实验，涵盖长文本、数字、日期、多音字和中英混合。全部生成有效音频，但中文数字表达、多音词和特殊单位仍有文本前端局限；实验不构成 macOS 性能或主观自然度结论。发布时仍须重新编译独立进程，并在各目标平台及安装包内执行实际语音验证。

## 准备和验证

需要 Node.js、curl、系统 tar 和 C 编译器。Windows 使用 x64 MSVC 开发环境；macOS 使用系统 C 编译工具；Linux 使用系统 C 编译工具。内置资源在构建过程中下载，缓存保存在 `.speech-runtime/downloads`；此构建缓存与用户下载的可选模型目录独立。现有缓存每次使用前都校验 SHA256，校验失败立即停止。

```sh
node scripts/speech-runtime.mjs prepare
node scripts/speech-runtime.mjs verify
```

可用 `--target windows-x64`、`--target macos-arm64`、`--target macos-x64` 或 `--target linux-x64` 显式指定目标，但必须在相同系统和架构的主机编译及验证。`prepare` 编译 `scripts/speech-runtime-runner.c`，直接链接官方 C API 库，精确编译和链接参数保存在准备脚本中。其 Windows 清单启用 UTF-8 进程代码页；输入文本文件、模型路径和输出路径支持中文。独立进程不调用 shell，不播放音频，不访问麦克风。

`verify` 使用唯一音色分别生成中文、中英混合、英文和慢速、快速中文样本，验证模型收到的中文未损坏、真实合成回调已结束、音频格式正确且具有可听样本；同时检查不同文本产生不同音频、语速变化与实际时长方向一致。验证输入和输出路径特意包含中文及空格。模型加载阶段保持不定进度；开始生成后回调报告实际句子批次完成比例。

## 安装目录

公共资源位于 `resources/speech/`：

```text
manifest.json          音色及模型调用路径
runtime.json           固定输入和每个资源文件的 SHA256
source-lock.json       构建时使用的固定清单
model/                 声学模型、声码器、字典及文本规范化数据
licenses/              原始许可证和声明
runtime/bin/           独立语音进程及 Windows 动态库
runtime/lib/           macOS、Linux 动态库
```

macOS 安装包将 `runtime/` 放入 `Contents/Helpers/speech/runtime/`，其余公共资源保留在 `Contents/Resources/speech/`。可执行文件保留相对动态库搜索路径 `@executable_path/../lib`。Windows 动态库与可执行文件放在同一目录。Linux 使用 `$ORIGIN/../lib`。

macOS 独立进程显式以 13.0 为最低系统版本编译，避免构建机器的系统版本意外提高安装要求。验证会读取独立进程及所有动态库的 Mach-O 架构和最低系统版本，拒绝与当前架构不符或要求高于 13.0 的组件。

准备阶段对独立进程及两份动态库逐一进行本地代码签名并严格验证，随后才记录最终文件哈希；不同架构不依赖编译器是否自动签名。应用打包时继续签名外层应用，安装后的语音验证再次检查每个独立组件的签名。

macOS 安装后验证：

```sh
node scripts/speech-runtime.mjs verify \
  --directory '/path/Open Media.app/Contents/Resources/speech' \
  --executable-directory '/path/Open Media.app/Contents/Helpers/speech' \
  --packaged
```

`--packaged` 只允许 macOS 可执行代码在应用签名时改变原二进制字节，仍逐字校验模型、音色、清单及许可证，并实际运行合成。Windows 安装后仍校验全部二进制哈希。应用不会用这些构建审计哈希限制用户替换独立组件。

## 完整对应源码

```sh
node scripts/speech-runtime.mjs sources --output speech-runtime-source.tar.gz
```

源码包根目录为 `speech-runtime-source/`，包括 `.speech-runtime/downloads/` 中全部固定归档、独立进程源码和 Windows 清单、精确构建脚本、模型原包、声码器原文件、许可证和本说明。源码与模型不省略，不能仅分发预编译库或链接列表。

源码范围包含：语音组件 1.13.8 完整原始源码和其中的发布工作流；实际使用的语音前端分支提交；所有通用构建依赖；推理库 1.28.2 完整源码、该二进制发布标签对应的构建工作流、CPU 和 macOS 平台所用依赖源码。推理库的 ONNX 子模块与固定 v1.22.0 归档对应同一提交。未使用的 GPU、训练、网页和模糊测试组件不进入已分发的 CPU 二进制，无须另外安装。

重新生成本项目独立进程：解压源码包，在目标平台按上述 `prepare`、`verify` 命令执行。准备脚本会从已提供且固定哈希的原始运行归档中提取 C API 头文件及链接库，重新编译独立进程；该步骤不需要重新下载归档。

若需修改推理库或语音前端，解压相应源归档和依赖。语音组件的 `cmake/download-all-deps.py` 和 `cmake/*.cmake` 记录依赖名称和构建选项；按各 CMake 文件的 `possible_file_locations` 中记录的本地文件名放置对应归档，可供上游 CMake 自动找到；固定清单的归档名用于避免不同依赖文件同名，不应直接照搬 URL 末尾的通用版本名。官方平台编译参数完整保留在其 `.github/workflows/linux.yaml`、`macos.yaml` 和 `windows-x64.yaml` 中。推理库对应发布的构建流程保留在 `onnxruntime-build` 归档的 `.github/workflows/`；其 CMake 输入记录在推理库 `cmake/deps.txt`。这些工作流包含上游为分发版本采用的库名和打包修改，不以未修改的上游发行版替代。修改后使用相同 C API 头文件与动态库重建独立进程。

原始归档中有大型测试数据，完整展开源码需要额外磁盘空间；发布源码包直接保留原始压缩归档。标准编译器、系统 SDK、CMake、Python 和打包工具由构建者安装。所有下载包的 SHA256 与出处均在固定清单中。

用户可在自己的安装副本中替换已重建的独立组件和模型。macOS 修改可执行文件或库后，对库、独立进程及应用副本重新执行系统代码签名工具的本地签名，即可使系统加载修改后的文件；应用不校验供应商签名密钥。无需项目私钥或外部激活服务。具体许可与原始文本见 `licenses/speech-runtime/README.md`。
