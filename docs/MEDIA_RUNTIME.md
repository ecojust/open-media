# 媒体运行时

桌面安装包包含独立执行的 `ffmpeg` 和 `ffprobe`。录制、媒体信息读取、时间线渲染和视频转换在本机进程中运行，不向远程服务上传媒体。网页环境的录制和图片处理使用浏览器提供的能力；完整视频导出需要桌面运行时。

## 固定源码与构建

`scripts/media-runtime.lock.json` 记录每一个媒体组件的版本、下载地址、SHA-256 和许可证。下载后必须通过校验，缓存中的文件校验失败也会终止构建。构建禁用自动探测额外依赖，避免无意链接构建机器上的库。项目不修改这些组件的源码。

工具链要求：Node.js 24、Bash、curl、tar、C/C++ 编译器、Make、Perl、pkg-config；x86 平台建议安装 NASM 以获得汇编优化。macOS 使用系统编译器，最低系统目标为 11.0。Windows 使用 MSYS2 的 MINGW64 环境，安装 `make diffutils perl nasm mingw-w64-x86_64-gcc mingw-w64-x86_64-pkgconf`；媒体工具为独立静态程序，应用壳使用原生桌面工具链。Linux 可以使用 GCC 构建和测试媒体工具。

```sh
node scripts/media-runtime.mjs prepare
bash scripts/build-media-runtime.sh
node scripts/media-runtime.mjs verify
```

构建目录为 `.media-runtime`，产物写入 `src-tauri/resources/media`。应用安装时将此目录放入资源目录的 `media` 下。运行时包含两份可执行文件、许可证原文、源码版本锁、实际构建配置和二进制校验清单。生成的文件不提交到源代码仓库。`MEDIA_BUILD_JOBS` 可控制并行任务数，默认 4。

验证脚本检查二进制校验和、宿主平台、版本、需要的编码器和滤镜，以及桌面平台的录制设备；随后真正编码带音频的视频、读取媒体信息，并导出图片和另一种视频格式。仅打印版本不会被当作验证成功。

测试可以通过 `OPEN_MEDIA_FFMPEG`、`OPEN_MEDIA_FFPROBE` 显式指定可执行文件。正式安装优先使用应用随附运行时。应用提供手动选择运行时的入口，供自行构建版本或排查问题时使用。

## 分发与对应源码

媒体工具启用 GPL 组件，因此作为独立程序按照 GPL-2.0-or-later 分发。Open Media 自有应用代码保持仓库的 MIT 许可证。每个组件的归属和许可证见 [第三方声明](../THIRD_PARTY_NOTICES.md)。

**每次发布包含媒体工具的安装包时，必须同时在相同下载页提供完整对应源码附件。** 不使用只列出上游地址或未来书面提供源码的方式代替该附件。

```sh
node scripts/media-runtime.mjs sources --output open-media-runtime-source.tar.gz
```

源码附件包含锁定的全部原始源码归档、构建脚本、版本和哈希清单、构建说明、项目许可与第三方声明。解压附件后可以直接运行上述构建命令，准备阶段优先读取附件中已提供的源码，无需重新下载媒体组件。每个原始源码归档保留版权、许可、专利声明及各自的构建说明。系统库和编译器使用目标操作系统工具链；它们不作为额外媒体库打包。

流水线分别上传 Windows x64、macOS ARM64、macOS x64 安装包及完整对应源码。发布流程核对相同提交、全部检查结果、附件 SHA-256 和构建信息，缺少对应源码时禁止发布。运行时缓存以平台、源码锁、下载脚本和构建脚本的内容哈希区分。

## 维护要求

更新任一组件时，同步更新源码锁的版本与实际下载哈希，重新编译三个桌面平台并完成实际媒体输出验证。保持 `--disable-autodetect`；如添加外部库，必须同时加入源码锁、构建步骤、许可证和对应源码附件。不能将临时下载的任意预编译工具替换到正式发行包中。
